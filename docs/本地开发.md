# 芒果签 — 本地开发

> 仓库根目录：`芒果签官网ui/`。后端模块名 `mangosign`，默认端口 **8199**。

## 1. 环境要求

| 工具 | 用途 |
|------|------|
| **Go 1.23+** | 后端（需 **CGO**） |
| **Node.js 18+** | 前端 Vite |
| **Homebrew**（macOS） | 编译本机 `libzsign`：`openssl`、`minizip` |
| **Docker**（可选） | 编 Linux 版 zsign/镜像，或本机跑 `mangosign:prod` |

## 2. 一次性准备

### 2.1 签名底包

有授权后台已发布版本时，官网用 **AES 加密 + IP 白名单** 调授权接口，取构建日期最新的已发布 IPA，再走下载接口缓存到 `resource/base/cache/`。

两边密钥必须一致；授权 `siteSign.allowIps` 必须包含官网出口 IP（失败响应里会带上 `client_ip`）。

```yaml
# 官网
sign:
  authBaseUrl: "https://auth.mangoios.com"
  authAesKey: "MangoSiteSign2026K7pQ2nR8wL4xH9vB"

# 授权
siteSign:
  aesKey: "MangoSiteSign2026K7pQ2nR8wL4xH9vB"
  allowIps:
    - "127.0.0.1"
    - "官网服务器公网 IP"
```

仅当授权没有已发布记录时，才回退 `backend/resource/base/base.ipa`。

### 2.2 本机 zsign 库（macOS，与 sign/backend 一致）

安装到 **`/usr/local/lib`**，**不要**写入 `build/zsign`（该目录仅 Linux Docker 产物）：

```bash
cd backend
make zsign-builder-mac   # 或 ./manifest/docker/build-zsign-mac.sh（需 sudo）
```

### 2.3 配置

编辑 `backend/manifest/config/config.yaml`，本地至少确认：

```yaml
server:
  address: ":8199"
sign:
  siteUrl: "http://localhost:8199"   # OTA / 短链根地址
  authBaseUrl: "https://auth.mangoios.com"
  authAesKey: "MangoSiteSign2026K7pQ2nR8wL4xH9vB"
  certMangoKey: "ZdzzTckgNQpSHnuR"   # 与授权 deviceAuth.certMangoKey 一致
```

## 3. 推荐：前后端分离开发

改 UI 最顺手；API 由 Vite 代理到 8199。

**终端 1 — 后端**

```bash
cd backend
export CGO_ENABLED=1
export CGO_LDFLAGS="-L/usr/local/lib"
export DYLD_LIBRARY_PATH=/usr/local/lib
go build -o main main.go
chmod +x run-local.sh
./run-local.sh ./main
```

GoLand 环境变量：`CGO_ENABLED=1`、`CGO_LDFLAGS="-L/usr/local/lib"`、`DYLD_LIBRARY_PATH=/usr/local/lib`（与 sign/backend 一致）。

**终端 2 — 前端**

```bash
cd frontend
npm install
npm run dev
```

浏览器打开 **http://localhost:5173**（`/api` 会代理到 `http://localhost:8199`）。

## 4. 可选：前后端一体（接近线上）

先构建前端静态资源到 `backend/resource/public/`：

```bash
cd frontend
npm ci
npm run build
```

再启动后端（同上 `./run-local.sh ./main`），访问 **http://localhost:8199**。

## 5. 可选：Docker 跑后端（与线上一致）

需已具备 Linux 产物（`make go-builder` 或 `./build-prod-image.sh`），且前端已 `npm run build` 打进 `resource/public`。

```bash
cd backend
docker load -i build/docker/mangosign_prod.tar   # 若本地还没有 mangosign:prod
docker run --rm -p 8199:8199 \
  -v "$(pwd)/manifest/config/config.yaml:/app/manifest/config/config.yaml" \
  -v "$(pwd)/resource/base/base.ipa:/app/resource/base/base.ipa" \
  mangosign:prod
```

## 6. 自检

```bash
curl -s http://localhost:8199/api/sign/health
```

## 7. 常见问题

| 现象 | 处理 |
|------|------|
| Mac 上 `Library not loaded: libzsign` | `make zsign-builder-mac`，并设置 `DYLD_LIBRARY_PATH=/usr/local/lib` 后重新 `go build` |
| Docker `file format not recognized` | `build/zsign` 被 Mac 库污染 → `rm -f build/zsign/libzsign.so && make zsign-builder` |
| 签名演示/失败 | 确认 `resource/base/base.ipa` 存在且 zsign 库已编好 |

更细的 zsign / Docker 分层构建见 [backend/manifest/docker/BUILD.md](../backend/manifest/docker/BUILD.md)。
