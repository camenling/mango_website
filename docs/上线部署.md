# 芒果签 — 上线部署

> 对齐 sign/backend：`build-prod-image.sh` 打镜像 → `pack-prod-deploy.sh` **打 zip** → 服务器 `docker load` **+** `docker compose up -d`。

---

## 一、本机：构建 + 打包（Mac，在 `backend/`）

### 1. 前端（打进部署 zip 的 `resource/public`，整目录挂载 /app）

```bash
cd ../frontend
npm ci && npm run build
```

### 2. 签名底包

线上优先用授权后台 **已发布且构建日期最新** 的 IPA。官网与授权用同一把 `authAesKey` / `siteSign.aesKey` 加密，且官网出口 IP 必须写入授权 `siteSign.allowIps`。第一次签名走授权下载接口，缓存到 `resource/base/cache/`。

`base.ipa` 只作「没有已发布版本」时的兜底，可选：

```bash
# 可选：放到 backend/resource/base/base.ipa（会打进 zip）
cp /path/to/工具.ipa backend/resource/base/base.ipa
```

### 3. 一键：镜像 + 部署 zip（推荐）

```bash
cd backend
chmod +x build-prod-image.sh pack-prod-deploy.sh

./pack-prod-deploy.sh --build        # 编 Go + 镜像 + 打 zip
# ./pack-prod-deploy.sh --build --full   # 含重编 zsign
```

**只需重打 zip（镜像已存在）：**

```bash
./pack-prod-deploy.sh
```

## 二、zip 里有什么（需拷贝到服务器的全部内容）


| 路径 | 说明 |
|------|------|
| `mangosign_prod.tar` | Docker 镜像（Go 二进制 + zsign 库） |
| `docker-compose.yaml` | 编排，`volumes: ./:/app` |
| `manifest/config/config.yaml` | 生产配置（**必改** `sign.siteUrl`、`sign.authBaseUrl`） |
| `.env` | Compose 变量（如 `MANGOSIGN_PORT`） |
| `resource/base/base.ipa` | 可选兜底底包（有已发布版本时可空） |
| `resource/public/` | 前端静态 + 空 `signed/`、`signTemp/` |
| `resource/temp/` | 临时目录 |
| `README.md` | 简要说明 |

**不需要**上传 Go 源码、`build/zsign`。解压目录即 compose 工作目录，**整体挂载为容器 `/app`**；改前端只需更新宿主机 `resource/public/`。

## 三、服务器：首次上线

```bash
# 上传 zip 到服务器，例如 /opt
unzip mangosign_deploy_*.zip -d /opt/mangosign
cd /opt/mangosign

vi manifest/config/config.yaml   # sign.siteUrl、sign.authBaseUrl、sign.certMangoKey（须与授权一致）
ls resource/public/index.html    # 应有前端

docker load -i mangosign_prod.tar
docker compose up -d
```

可选 Redis（多实例 / 短链持久化）：在 `manifest/config/config.yaml` 取消注释 `redis` 段，并：

```bash
docker compose --profile redis up -d
```



### HTTPS 与 Nginx（宝塔）

服务在 **Docker 内 8199**，站点目录 **不要** 当 PHP 静态站用；整站反代到本机即可。

1. `manifest/config/config.yaml` 里 **`sign.siteUrl: "https://sign.mangoios.com"`**（与证书域名一致），并确认 **`sign.certMangoKey`** 与授权 `deviceAuth.certMangoKey` 为同一把 16 字节钥匙。
2. 服务器上 Docker 已启动：`curl -s http://127.0.0.1:8199/api/sign/health` 有响应。
3. 宝塔站点里 **关掉 PHP**、注释 **`root`**、**`enable-php`**、**`rewrite`**。
4. **务必注释或删除** 面板自带的静态资源规则，否则 `.js`/`.css` 会从 `root` 读磁盘而不是反代（表现为 **index 能开、`/assets/*.js` 404**）：
   - `location ~ .*\.(gif|jpg|jpeg|png|bmp|swf)$`
   - `location ~ .*\.(js|css)?$`
5. 在「配置文件」中保留面板的 **SSL / `.well-known`** 段，在 **443**（或暂仅 **80** 测试）增加：

```nginx
# 上传 P12 + 描述文件，与 manifest/config/config.yaml clientMaxBodySize 一致
client_max_body_size 50m;

location / {
    proxy_pass http://127.0.0.1:8199;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_connect_timeout 60s;
    proxy_send_timeout 300s;
    proxy_read_timeout 300s;
}
```

以下路径均由 Go 处理，**无需**单独 location：`/`、`/install`、`/api/*`、`/i/*`（短链）、`/getInstallPlist/*`、`/signed/*`（IPA/plist）。

**仅 HTTP、尚未上证书时**：在 `listen 80` 的 server 里只加上面 `client_max_body_size` + `location /` 即可（OTA 真机安装仍需 HTTPS）。

**已有 443 证书时**：`listen 80` 可只做 `return 301 https://$host$request_uri;`，反代写在 `listen 443 ssl` 的 server 里。

完整宝塔示例见 [backend/deploy/nginx-sign.example.conf](../backend/deploy/nginx-sign.example.conf)。

### 自检

```bash
curl -s http://127.0.0.1:8199/api/sign/health
curl -sI http://127.0.0.1:8199/assets/   # 应 200 或 403，不应连不上
curl -sI https://sign.mangoios.com/assets/index-*.js  # 浏览器 Network 里看到的文件名
```

## 四、更新发版

1. 本机：`npm run build` → `./pack-prod-deploy.sh --build`
2. 上传新 zip 或仅替换 `mangosign_prod.tar`
3. 服务器：`docker load -i mangosign_prod.tar && docker compose up -d`
  保留 `manifest/`、`resource/public/signed`、`resource/temp`；仅换镜像或同步新的 `resource/public` 静态文件

## 五、分步构建（与 sign/backend 相同）

```bash
make zsign-builder    # 仅 Linux libzsign → build/zsign
make go-builder       # Linux main → build/go/main
make docker-prod      # mangosign:prod + mangosign_prod.tar
```
